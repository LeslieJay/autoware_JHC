# 仿真下停车位置误差分析

> 用一个 10 点轨迹示例，逐项拆解为什么仿真也无法做到"零误差"停车，以及如何把误差压到 mm 级。

---

## 1. 场景设定

- `goal_pose`: `(10.000, 0.000)`，朝向沿 +x 轴
- 控制周期：30 ms
- 仿真车辆模型：`DELAY_STEER_ACC_GEARED`（默认）
  - `acc_time_delay = 0.1 s`
  - `acc_time_constant = 0.1 s`
- 控制器：trajectory_follower（PID + Pure Pursuit）

---

## 2. 五个误差来源（按对最终位置的影响排序）

### 2.1 规划侧离散化（影响最大）

`behavior_path_planner` 的 `output_resolution = 0.5 m`，把"goal=(10.000, 0.000)"重采样到最近的轨迹点：

| idx | x (m) | v_target (m/s) | 备注 |
|---|---|---|---|
| 0 | 5.50 | 2.000 | 巡航 |
| 1 | 6.00 | 2.000 |  |
| 2 | 6.50 | 1.800 |  |
| 3 | 7.00 | 1.500 |  |
| 4 | 7.50 | 1.200 |  |
| 5 | 8.00 | 0.900 |  |
| 6 | 8.50 | 0.600 |  |
| 7 | 9.00 | 0.300 |  |
| 8 | 9.50 | 0.100 | ← **轨迹末点**，**不是 10.000** |
| 9 | — | — | 没有第 10 个点 |

**离散化误差 = 10.000 − 9.500 = 0.500 m**。控制器最远只能跟到 `x=9.5`，**根本看不见 `x=10.000`**。

> （实际 Autoware 末点 v 是 0，这里写 0.1 是为了让"车辆延迟"看得更清楚）

链路：
- `mission_planner` 把 `goal_pose` 投影到最近 lanelet centerline；
- `behavior_path_planner` 转成离散轨迹点（`output_resolution ~0.5 m`）；
- `velocity_smoother` 重采样后终点又被吸附到最近样点。

→ 每一步都有 cm 级离散化误差累积。

---

### 2.2 控制器是闭环跟踪、不是定点投影

Pure Pursuit / MPC / Trajectory Follower 跟的是**轨迹点序列**，不是绝对终点 `(10, 0)`。

idx=7 附近的行为：

| t (ms) | ego_x | ego_v | 跟踪目标 idx | 指令 v |
|---|---|---|---|---|
| 0 | 9.000 | 0.30 | 8 (9.50) | 0.30 |
| 30 | 9.009 | 0.30 | 8 | 0.20 |
| 60 | 9.015 | 0.20 | 8 | 0.10 |
| 90 | 9.018 | 0.10 | 8 | 0.10 ← **指令进入死区** |

当 ego 到达 `idx=8 (x=9.5)` 附近、速度 ≤ `stop_state_entry_target_speed (默认 0.01 m/s)` → 进入 `STOPPED`。  
**车停在 x ≈ 9.50**，不是 10.000。

横向同理：横向控制有 lookahead，本质上对终点附近的"剩余横向偏差"无法做到零误差。

---

### 2.3 车辆模型延迟 + 速度死区（仿真也有）

即使指令在 t=90 ms 就发了 `v=0`，`DELAY_STEER_ACC_GEARED` 一阶延迟响应：

```
t=  90 ms: 指令 v=0,   实际 v=0.100 m/s
t= 120 ms: 指令 v=0,   实际 v=0.087 m/s
t= 150 ms: 指令 v=0,   实际 v=0.064
t= 200 ms: 指令 v=0,   实际 v=0.037
t= 300 ms: 指令 v=0,   实际 v=0.013
t= 400 ms: 指令 v=0,   实际 v=0.005 → 进入 STOPPED
```

这 310 ms 滑行了：

$$\int_{0.09}^{0.4} v(t)\,dt \approx \tfrac{1}{2} \cdot 0.1 \cdot 0.31 \approx 0.0155\ \text{m} \approx \mathbf{1.5\ cm}$$

**最终停车位置 ≈ 9.50 + 0.015 = 9.515 m**

---

### 2.4 状态机阈值容忍带 → 误差被冻结

`mission_planner` 检查：

```
distance_to_goal = |10.000 - 9.515| = 0.485 m
threshold        = 3.0 m         ← goal_distance_threshold 默认
0.485 < 3.0  →  ArrivedGoal ✓
```

Autoware 直接宣布"到达"，状态切到 `WaitingForRoute`，**控制器从此不再发任何修正指令**。误差 0.485 m 被永久冻结。

相关默认阈值：

| 参数 | 默认 |
|---|---|
| `arrival_check_distance` (mission_planner) | 1.0 m |
| `goal_angle_threshold_deg` | 45° |
| `stop_state_entry_target_speed` (控制器) | 0.01 m/s |
| `stop_state_entry_duration_time` | 0.1 s |

---

### 2.5 数值精度与时间步长（不可消除）

控制周期 30 ms、定位/里程计噪声、float32 累积——会贡献 **±0.5 mm** 级抖动。物理上消不掉。

---

## 3. 误差账本

| 来源 | 本例贡献 |
|---|---|
| ① 规划离散化（轨迹末点 9.5 vs goal 10.0） | **−0.500 m** |
| ② 控制器跟轨迹序列、不跟绝对位置 | 不直接产生误差，但让 ① 和 ③ 的误差**无法被纠正** |
| ③ 车辆延迟 + 速度死区滑行 | **+0.015 m** |
| ④ 状态机 3 m 阈值 → 提前结束 | 让 ①③ 永远不会被修正 |
| ⑤ 数值抖动 | ±0.0005 m |
| **合计停车误差** | **≈ 0.485 m** |

---

## 4. 用户实测 1.5 cm 是什么情况

实测 `dx=−0.012 m, dy=−0.008 m`，平面误差 ≈ 1.5 cm，说明工程里：

- **① 离散化误差几乎为 0**：已把 `output_delta_arc_length` 调小，且 `enable_correct_goal_pose: false` 让 mission_planner 不把 goal 对齐到 lanelet 中心线
- **剩下的 1.5 cm 主要来自 ③**：仿真车辆模型延迟 + PID 速度环死区导致的滑行

---

## 5. 把误差压到 mm 级的关键修改

按效果由强到弱：

| 修改 | 文件 | 主要消除的误差 |
|---|---|---|
| `vehicle_model_type: IDEAL_STEER_VEL` + 清零 delay/time_constant | `byd_vehicle_description/config/simulator_model.param.yaml` | **③（最关键）** |
| `stopped_state_entry_vel: 0.001` 等 | `pid.param.yaml` | ② 提前停 |
| `arrival_check_distance: 0.01` | `mission_planner.param.yaml` | ④ 状态机不主动放弃 |
| `output_delta_arc_length: 0.05`（path_optimizer/path_sampler/elastic_band） | 三处 yaml | ① 离散化 |
| `resample_ds: 0.02` | `velocity_smoother.param.yaml` | ① 离散化 |
| `kp/ki` 提升 + `enable_integration_at_low_speed: true` | `pid.param.yaml` | ③ 末段死区 |

理想情况下可达 **< 2 mm**。真正的 0 不可能（原因 ⑤）。

---

## 6. 工程结论

- **1~2 cm 是可接受的工程精度**（实车 GNSS RTK 噪声本身就有几 cm），追求 0 误差对实际功能没意义。
- 若必须更准（例如对接停车桩、特殊试验场景），用本仓库的 [goal_position_holder](../../src/byd/goal_position_holder/README.md) 节点在控制管线末端做位置 PD 闭环，可把误差稳定压到 **±2 cm**，且不依赖仿真模型。
